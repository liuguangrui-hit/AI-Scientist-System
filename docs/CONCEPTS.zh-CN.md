# 动态假设-证据森林

本系统的核心设计只有一条，其余设计均由此推出：**假设是全局实体，不属于任何一个课题。**

常见做法是每个课题维护一棵独立的假设树，树与树之间互不关联。其结果是同一条假设在三个课题中被分别验证三次；
一次实验否定了它，另外两个课题仍按原假设继续推进。本系统将所有课题的假设置于同一片森林中：
树表示各课题自身的论证结构，节点所指向的假设则由各课题共享。

---

## 1. 森林的构成

```
idea（课题）          一棵树，代表一条论证路线
  └─ node（节点）     树里的一个位置：k=1.2.1、parent、role
       └─ hyp        节点指向的假设 —— 全局唯一，可被多棵树同时指向
```

三者的关系为：**树拥有节点，节点引用假设，假设不属于任何树。**

同一条假设 `H-02` 可以：

| 在哪棵树 | 处在什么位置 | 这棵树怎么用它 |
| --- | --- | --- |
| P-014 | 第 2 层中间节点 | 本课题自证，向上支撑父节点 |
| P-016 | 根前提 | 直接采纳，不再分解，作为整条论证的起点 |
| P-017 | 已证叶子 | 作为已验证前提引用，无需重复实验 |

位置由**各棵树自身的论证结构**决定，而非假设本身的属性。后文所述的全部行为均源于此。

### 角色（role）

每个节点标明其对所指假设的处理方式：

- `own_to_prove` —— 由本课题自行证明，并继续分解为子假设；
- `borrowed_assumption` —— 借用前提，直接采纳，不再展开。

同一条假设在 A 树里是 `own_to_prove`，在 B 树里可以是 `borrowed_assumption`。

---

## 2. 证据是带符号的增量

每次实验结束后，向**假设**（而非假设树）写入一条证据：

```json
{ "exp": "e_15", "idea": "P-014", "delta": 0.6, "note": "七档拟合 R²=0.98", "at": "..." }
```

- `delta` 有正负。累加得到该假设的**累积分数**。
- `idea` 记录该证据产生于哪个课题。证据有来源，但不从属于该课题。
- 累积 ≥ **+1.0** 转 `self_verified`；≤ **−1.0**，或连续三次 `PIVOT` 无改善，升级到裁定队列。

**一次写入，所有引用方同时更新。** 这是共享假设最直接的收益：三个课题共用的 baseline 只需重测一次，
三个课题的下游节点即同时解冻，无需分别重复实验。

### 状态由计算得出

界面所显示的状态均为**派生结果**，不作存储：

```
有实验正在运行          → testing
已提交裁定              → pending_review
累积 ≥ +1.0             → self_verified
有证据但未达阈值        → active
无实验、无证据          → untested
```

因此不会出现“状态为已验证而累积证据为负”的矛盾。

---

## 3. 可执行假设（frontier）

可执行假设（frontier）是全局范围内依赖已满足、可直接进行实验的假设集合。一条假设进入该集合须同时满足以下条件：

1. 它的 `depends_on` 全部 `self_verified`；
2. 没有针对它正在运行或排队中的实验；
3. 所在节点没有被裁定冻结；
4. 它尚未结清（已验证且无需复验的假设不再列入）；
5. **它至少在一棵树中是叶子** —— 有子节点的主张由其子节点结清，不直接进行实验。

可执行假设跨全部课题排序，优先安排关联多个课题的假设。调度由此归结为一个具体问题：
*在一个空闲并发执行上，验证哪条假设的收益最大？*

---

## 4. 裁定：同一个失效，三种后果

当证据相互矛盾，或连续三次更换方法均无改善时，executor **停止展开该假设**，
并提交研究者裁定。这是系统中唯一需要等待人工决策的环节。

裁定所回答的问题不是“该假设是否成立”，而是“若判定其不成立，各课题分别受到何种影响”：

| 它在该树里的位置 | 后果 | 影响范围 |
| --- | --- | --- |
| 根前提 | 整棵树的节点回到 `untested`，已撰写的章节须重写 | **global** |
| 中间节点 | 冻结其下游子树，相关排队实验撤下 | **branch** |
| 叶子，且本课题有独立正证据 | 不受影响 | **local** |

四种裁定结果：

- `close` —— 判定不成立并关闭，按上表传播冻结；
- `return_active` —— 证据不足以判定，附新方向退回可执行队列；
- `narrow_scope` —— 改写 claim 缩小适用范围后重开（保留正证据，丢弃范围外的负证据）；
- `downgrade` —— 降级为借用前提，标注未验证。

**裁定只写入 `verdicts/<hyp>.json`，节点状态由裁定派生。** reviewer 不直接修改假设树。
这一边界是有意设计的：每个文件的写入方固定，任何错误均可追溯到具体的人或 agent。

---

## 5. 三个 agent 的写入边界

| agent | 只写 | 不能碰 |
| --- | --- | --- |
| surveyor | `index.jsonl`、`sources/`、游标 `state.json` | 假设树、裁定 |
| executor | `events.jsonl`、`artifacts/`、实验记录 | `tree.json` 里的状态、裁定 |
| reviewer | `verdicts/` | 树结构、实验产物 |
| 研究者 | 裁定、提交实验、批准立项 | —— |

在此设计下，任何一方都不能既产生证据又裁定证据。

---

## 6. 实验树：假设的验证过程

假设树回答“需要证明什么”，实验树回答“如何验证”，共分四个阶段：

```
初探 probe   →  调参 tune  →  主实验 main  →  消融 ablate
```

- 节点分为**新建 / 修复 / 改进**三类；失败节点**予以保留**，以避免重复同样的错误；
- 只有标记为“代表节点”的结果写入假设树，其余结果保留在实验树中作为记录；
- 一整张档位 × 种子扫描矩阵最终**只产生一条证据**。写入的是“趋势成立，相邻档位不可区分”这一结论，
  而不是 18 个数值。

---

## 7. 写作是证据的另一种视图

论文章节由假设树映射而来：节点状态发生变化时，对应小节自动标记为待更新。

- 每一条断言都须能追溯到其对应的假设与实验 id；
- 系统检出“任何”“普遍”“始终”等措辞，并与证据所记录的**适用范围**进行核对；
- 存在未修正的过度声称时，投稿版本无法导出，系统列出相应条目。

写作中发现的证据缺口（例如某段仅由单次运行支撑）直接返回实验队列，形成闭环。

---

## 8. 研究者的职责

以下三项决策由研究者作出，系统不代为决定：

1. **确定方向** —— 来源白名单、研究主题、是否立项；
2. **裁定假设** —— 证据矛盾时的取舍；
3. **决定投稿** —— 判断论文何时完成。

其余工作，包括采集、分级、归纳、安排实验、剪枝、重试、绘图与主张核查，均由系统自动完成，
每一步记录于 `events.jsonl`。
